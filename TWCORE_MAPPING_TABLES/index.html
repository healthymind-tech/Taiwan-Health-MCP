    TWCore Mapping Tables — Resource Conversion Spec¶

    對照來源：你的院內輸入 JSON → 正確解答 FHIR Bundle

    0. 通用規則¶

    0.1 Cross-Reference 規則¶

    所有院內 ID（patientId: "1"、encounterId: "1"）在 Bundle 內都被換成 urn:uuid:xxx，靠 ResourceType + 院內 ID 決定目標：

    輸入                          →  Bundle 內的 Reference
───────────────────────────────────────────────────────
patients[].id: "1"           → Patient/{uuid}
organizations[].id: "1"      → Organization/{uuid}
encounters[].id: "1"         → Encounter/{uuid}
practitioners[].id: "1"      → Practitioner/{uuid}
practitionerroles[].id: "1"  → PractitionerRole/{uuid}
conditions[].id: "1"         → Condition/{uuid}
observationVitalSigns[].id: "1" → Observation/{uuid}

    0.2 Code Lookup 規則¶

    院內 code 查詢方式 標準 system
    conditionCode, reasonCode SNOMED（依 conditionText 或 reasonCode 文字） http://snomed.info/sct
    observationCode 對應到 vital signs LOINC http://loinc.org
    roleCode, specialtyCode SNOMED http://snomed.info/sct
    qualificationCode SNOMED http://snomed.info/sct
    serviceType service-type value set（"emergency" → "117"） http://terminology.hl7.org/CodeSystem/service-type
    severity 已是 SNOMED，直接貼 http://snomed.info/sct
    gender 保留字串（已符合 FHIR enum） —
    type: "prov" organization-type value set http://terminology.hl7.org/CodeSystem/organization-type

    院內 Code 資源 FHIR 欄位 查詢 system 預期結果

    "emergency" Encounter serviceType.coding[0].code service-type CS "117"

    9. 一般查詢（自然語言 → 標準 code）¶

    除了上面的院內 code lookup，這條賽道也需要從 中文敘述 查標準 code。這可以依靠現有的 search_snomed、search_loinc 工具，或由 twcore_batch_transform 調用：

    資源 輸入文字 要查什麼 預期結果
    Condition conditionText: "突發胸痛" SNOMED 57054005
    Encounter reasonCode 隱含 "胸痛" SNOMED 22298006

    10. 輸入欄位對應決定邏輯¶

    twcore_batch_transform 如何決定哪些輸入欄位對應到哪個 resource type：

    # 對應邏輯：
input_has("patients")            → FHIRPatientService
input_has("organizations")        → FHIROrganizationService
input_has("practitioners")        → FHIRPractitionerService
input_has("practitionerroles")    → FHIRPractitionerRoleService
input_has("encounters")           → FHIREncounterService
input_has("conditions")           → FHIRConditionService
input_has("observationVitalSigns") → FHIRObservationService (vital-signs mode)

    各 service 內部循環處理該 array 的每個 item，並自動維護 cross-reference map 供後續解析使用。
